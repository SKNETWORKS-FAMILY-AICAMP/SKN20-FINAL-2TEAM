## 학습 가이드

### 컬럼 구조

| 컬럼 | 역할 | 학습(input) | 학습(output) | 테스트 |
|------|------|:-----------:|:------------:|:------:|
| user_query | 사용자 제품/기술 설명 | O (입력 1) | | O (입력) |
| claim_reg | 등록 청구항 | O (입력 2) | | O (입력) |
| claim_pub | 공개 청구항 (금반언 비교용) | O (입력 3) | | O (입력) |
| components | 청구항 핵심 구성요소 | O (입력 4) | | O (입력) |
| apply_num | 출원번호 | O (입력 5, 메타) | | O (입력) |
| regit_num | 등록번호 | O (입력 5, 메타) | | O (입력) |
| pub_num | 공개번호 | O (입력 5, 메타) | | O (입력) |
| output_form | FTO 분석 결과 | | O (정답) | 정답 비교용 |
| **label** | **라벨** | **X (제외!)** | | 정답 비교용 |

### 학습 데이터 구성 (중요!)

### "instruction" (System Prompt (학습 + 추론 동일하게 사용))

```
당신은 화장품 특허 침해(FTO) 분석 전문가입니다.

[문구 규칙]
- "판단"이라는 단어 사용 금지 → "분석"으로 대체
- "리스크" 사용 금지 → "가능성"으로 대체

[분석 규칙]
- 구성요소 완비의 원칙: 모든 구성요소를 포함해야 침해
- 균등론: 특허 구성 수치가 경미하게 이탈 시 전문가 검토 대상
- 금반언: 공개청구항에는 있었지만, 등록청구항에는 삭제된 구성은 침해 주장 불가
- 내재성: 성분 동일 + 용도/효과 미언급 시 "미대응(내재성)"

[대응 여부]
- 대응: 동일/포함
- 미대응: 해당 구성 없음
- 미대응(균등): 수치 경미 이탈
- 미대응(내재성): 용도/효과 미언급
- 확인불가: 정보 부족

[출력 형식]
◆구성 대비◆ → 테이블
◆판단◆ → 분석 설명 (결론성 문구 금지)
◆결론◆ → 아래 4개 중 하나만:
- "침해 가능성이 높은 것으로 분석됩니다."
- "침해 가능성이 낮은 것으로 분석됩니다."
- "전문가의 추가 검토가 권고됩니다."
- "침해 여부 분석을 위해 보다 구체적인 실시 정보가 필요합니다."
```

```
[Input - 프롬프트]                              [Output - 정답]
① user_query   → 뭘 만들려는지                  output_form
② claim_reg    → 특허가 뭘 보호하는지            (모델이 이걸 생성하도록 학습)
③ claim_pub    → 금반언 비교용
④ components   → 핵심 구성요소
⑤ apply_num, regit_num, pub_num → 메타정보

※ label 컬럼은 학습에 넣지 않는다!
```

- **Input**: ①~⑤를 위 순서대로 프롬프트로 구성
- **Output (정답)**: output_form 전체 (모델이 이걸 생성하도록 학습)
- **label**: 학습에 포함하지 않음. 모델이 output_form을 생성하면 ◆결론◆ 문구에서 라벨을 추출하는 구조
- **메타정보 필수**: output_form에 regit_num이 포함되어 있고, RAG에서 메타정보를 입력으로 제공하므로 학습 시에도 반드시 포함


### 주의사항

- **label 컬럼은 학습에 절대 포함하지 않는다.**
- 테스트 시에도 label은 모델에 넣지 않고, 평가 스크립트가 예측 라벨 vs 정답 라벨을 비교하는 데 사용한다.
- **학습과 추론에서 반드시 동일한 System Prompt를 사용해야 한다.**
- **output_form의 마크다운 테이블 형식도 모델이 그대로 생성해야 한다.** 테이블이 깨지면 파싱 불가.

### 프로덕션 배포 전 필수 작업

- **RAG 특허 DB 80,000건에 대해 components 추출 후 DB에 저장해야 한다.**
- sLLM은 components를 input으로 받아서 비교/판단만 수행하는 구조이므로, RAG가 특허 검색 시 components도 함께 반환해야 한다.
- Gemini 2.0 Flash로 80,000건 추출 시 비용 ~2만원, 시간 ~반나절 소요.
- components 없이 sLLM에 claim만 넣으면 1B/1.5B 모델이 구성요소 추출까지 해야 하므로 품질이 크게 떨어진다.

## 전체 워크플로우

```
[학습]                              [평가]
sllm_train_2869.xlsx                sllm_test_718.xlsx
  → Gemma/Qwen QLoRA 파인튜닝        → 01_infer.py (모델 추론)
  → 학습 완료된 모델                    → 02_evaluate.py (개별 평가)
                                       → 03_compare.py (모델 비교)
                                       → eval_summary.md (최종 리포트)
```

### Step 1: 모델 학습 (각자 환경에서)

Gemma3 1B / Qwen2.5 1.5B를 `sllm_train_2869.xlsx`로 QLoRA 파인튜닝

### Step 2: 모델 추론 (`eval/01_infer.py`)

학습 완료된 모델로 테스트 718건 추론

```bash
cd data/sllm/eval/

# Gemma
python 01_infer.py --model_path ./gemma-fto --model_name gemma --test_data ../sllm_test_718.xlsx

# Qwen
python 01_infer.py --model_path ./qwen-fto --model_name qwen --test_data ../sllm_test_718.xlsx
```

출력: `output/infer_gemma.xlsx`, `output/infer_qwen.xlsx`
(원본 테스트 데이터 + pred_output 컬럼 추가)

### Step 3: 개별 모델 평가 (`eval/02_evaluate.py`)

```bash
python 02_evaluate.py --input output/infer_gemma.xlsx --model_name gemma
python 02_evaluate.py --input output/infer_qwen.xlsx --model_name qwen
```

출력: `output/eval_detail_gemma.xlsx`, `output/eval_detail_qwen.xlsx`
(행별로 라벨일치 O/X, 섹션완성 O/X, 법리일관성 O/X 등)

### Step 4: 두 모델 비교 (`eval/03_compare.py`)

```bash
python 03_compare.py \
    --model_a output/eval_detail_gemma.xlsx \
    --model_b output/eval_detail_qwen.xlsx
```

출력: `output/eval_summary.md` (종합 비교 리포트)

### 평가 항목

| # | 항목 | 설명 |
|---|------|------|
| 1 | 라벨 정확도 | ◆결론◆에서 키워드로 라벨 추출 → 정답과 비교 (precision/recall/F1) |
| 2 | 구조 완성도 | ◆구성 대비◆, ◆판단◆, ◆결론◆ 3섹션 존재 여부 |
| 3 | 행 수 일치 | 정답 vs 예측의 구성대비표 행 수 비교 |
| 4 | 법리 일관성 | 라벨 vs 대응분석표 논리 정합성 (침해+미대응=X, 비침해+전부대응=X, 전문가+균등내재성없음=X) |

### 라벨 매핑 규칙

◆결론◆ 섹션에서 키워드 기반으로 매핑 (우선순위 순):

| 순위 | 키워드 | 라벨 |
|------|--------|------|
| 1 | "전문가" | 침해_전문가 |
| 2 | "구체적인 실시 정보" 또는 "추가 정보" | 애매 |
| 3 | "가능성이 낮" | 비침해 |
| 4 | "가능성이 높" | 침해 |
| - | 해당 없음 | 매핑실패 |
