# 1차 결과 개선 - CLIP ViT-B/32 파인튜닝 설정

## 1. 배경 및 목적

원본 CLIP(ViT-B/32)은 범용 이미지-텍스트 표현을 위한 모델로, 특허 디자인 도면 도메인에 특화되어 있지 않습니다.
이 프로젝트에서는 같은 출원번호의 다른 도면(slot-0, slot-1)이 임베딩 공간에서 가까워지도록, 다른 출원번호의 도면은 멀어지도록 파인튜닝합니다.

**학습 방식**: Triplet Margin Loss
- anchor: 기준 이미지 (slot-0)
- positive: 같은 출원번호의 다른 도면 (slot-1) → anchor와 가까워야 함
- negative: 다른 출원번호 이미지 → anchor와 멀어야 함

## 2. 데이터셋

| 항목 | 값 |
|------|-----|
| 전체 triplets | 41,792개 |
| hard negative | 20,318개 (같은 물품명, 다른 출원) |
| easy negative | 21,474개 (다른 물품명, 다른 출원) |
| Train / Val 분할 | 90% / 10% = 37,613 / 4,179 |

- **hard negative**: 같은 물품명(예: "화장품용 포장용기")이지만 다른 출원번호의 이미지. 모델이 세부 디자인 차이를 학습하게 강제함.
- **easy negative**: 아예 다른 물품명의 이미지. 기본적인 카테고리 분리 학습.

## 3. 하이퍼파라미터 설정 및 근거

### EPOCHS = 30

| 선택 근거 |
|-----------|
| 이전 InfoNCE 학습(train.py, 100 epoch)에서 Epoch 10 부근에서 R@1 peak 후 오버피팅 관찰됨. |
| Triplet Loss는 InfoNCE보다 샘플 효율이 낮아 더 많은 epoch이 필요하지만, 데이터가 충분(41,792 triplets)하므로 30 epoch으로 설정. |
| ReduceLROnPlateau(patience=3)가 정체 시 LR을 자동으로 절반으로 줄여 오버피팅을 억제함. |

---

### BATCH_SIZE = 32

| 선택 근거 |
|-----------|
| MPS(Apple Silicon GPU) 메모리 한계를 고려한 값. CLIP ViT-B/32의 1회 포워드 패스는 약 512차원 임베딩 × 3(anchor, positive, negative) = 메모리 부담이 적음. |
| 16보다 크면 학습 안정성이 높고, 64보다 작으면 MPS 메모리 초과 위험 없음. |
| Triplet Loss는 InfoNCE와 달리 in-batch negative를 사용하지 않으므로 배치 크기가 loss 품질에 직접적인 영향을 주지 않음. 32는 속도와 안정성의 균형점. |

---

### LR = 1e-5 (0.00001)

| 선택 근거 |
|-----------|
| CLIP은 대규모 사전학습 모델로, 높은 LR로 파인튜닝 시 "Catastrophic Forgetting" 발생 → 기존에 학습된 풍부한 시각 표현이 손상됨. |
| 일반적으로 CLIP 파인튜닝에서 권장되는 LR 범위는 1e-6 ~ 5e-5. 1e-5는 그 중간값으로 충분한 학습 속도와 기존 표현 보존을 동시에 달성. |
| AdamW의 weight_decay=1e-4와 함께 사용해 L2 정규화 효과를 추가. |

---

### MARGIN = 0.2

| 선택 근거 |
|-----------|
| Triplet Margin Loss 목표: `d(anchor, positive) + margin < d(anchor, negative)` |
| margin이 너무 작으면(예: 0.05) positive와 negative의 분리가 불충분 → 검색 시 유사도 구분이 어려움. |
| margin이 너무 크면(예: 0.5 이상) 학습이 수렴하지 않음 (loss=0인 triplet이 없어져 gradient 소멸). |
| 코사인 거리 기준으로 0.2는 임베딩 공간에서 명확한 분리 마진을 제공하는 표준값 (FaceNet, metric learning 논문 참조). |

---

### HARD_RATIO = 0.7

| 선택 근거 |
|-----------|
| hard negative(같은 물품명, 다른 디자인)는 모델이 세밀한 디자인 차이를 학습하게 하는 핵심 샘플. |
| easy negative(다른 물품명)만 사용하면 모델이 "화장품 vs. 자동차"처럼 쉬운 분류만 학습 → FTO 목적에 부적합. |
| hard 70% + easy 30% 비율은 어려운 케이스를 충분히 학습하되, easy sample로 기본 표현도 유지하는 균형점. |
| 100% hard negative는 학습 불안정(loss가 진동) 위험이 있어 피함. |

---

### VAL_RATIO = 0.1

| 선택 근거 |
|-----------|
| 전체 41,792 triplets 중 10% = 4,179개를 검증셋으로 사용. |
| 데이터가 충분하므로 15~20%까지 늘릴 수 있지만, 학습셋을 최대한 확보하기 위해 10%로 설정. |
| 검증셋은 epoch마다 val_loss, d_pos, d_neg, gap을 계산해 오버피팅 감지 및 best model 저장에 활용. |

## 4. 모델 Freeze 전략

```
CLIP ViT-B/32 총 12개 Transformer Block
├── Block 0~7  → 완전 동결 (기존 CLIP 시각 표현 보존)
└── Block 8~11 → 학습 가능 (마지막 4 블록)
    + Visual Projection Layer → 학습 가능
```

| 선택 근거 |
|-----------|
| 전체 파인튜닝 시 Catastrophic Forgetting 위험 + 과적합 위험 + 학습 시간 급증. |
| 앞쪽 블록은 저수준 특징(엣지, 텍스처)을 담당 → 특허 도면에도 공통적으로 유효. |
| 뒤쪽 블록은 고수준 의미 표현을 담당 → 특허 도면 도메인에 맞게 재학습 필요. |
| 학습 파라미터: 28,744,704 / 151,277,313 = **19.0%** (속도와 품질의 균형). |

## 5. 모니터링 지표

| 지표 | 의미 | 목표 방향 |
|------|------|-----------|
| `train_loss` | 학습셋 triplet loss | 감소 |
| `val_loss` | 검증셋 triplet loss | 감소 (train보다 높으면 오버피팅) |
| `d_pos` | anchor ↔ positive 평균 거리 | 감소 (같은 출원 도면이 가까워짐) |
| `d_neg` | anchor ↔ negative 평균 거리 | 증가 (다른 출원 도면이 멀어짐) |
| `margin_gap` = d_neg - d_pos | 분리 정도 | **증가** (클수록 검색 성능 좋음) |
