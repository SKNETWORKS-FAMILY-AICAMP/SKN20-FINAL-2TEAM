## 1. 시스템 개요

본 시스템은 특허청 디자인 도면 이미지를 기반으로 **유사 디자인을 자동 검색**하는 시스템입니다.
사용자가 디자인 도면 이미지를 업로드하면, 벡터 데이터베이스(ChromaDB)에서 Hybrid Retrieval 방식으로 유사 디자인 Top-10을 반환합니다.

### 핵심 특징

| 항목 | 내용 |
|---|---|
| 임베딩 모델 | CLIP ViT-B/32 (OpenAI) |
| 임베딩 차원 | 512차원 |
| 벡터 DB | ChromaDB (코사인 거리) |
| 검색 방식 | Hybrid: Dense (0.8) + BM25 (0.2) |
| 이미지 전처리 | Canny Edge Detection → 스케치 변환 |
| 총 데이터 수 | 21,829건 |
| 디바이스 | Apple Silicon MPS |

## 2. 파이프라인 구성

```
[원본 데이터]
data/json/  (21,909개 JSON 파일)
      │
      ▼
[embeddings_v2.py]
  1) JSON에서 이미지 URL 추출 및 다운로드
  2) 사진/스케치 자동 감지 (흰색 비율 >95%, 평균 밝기 >250 → 스케치 판정)
  3) 사진인 경우 → Canny Edge Detection 스케치 변환
     · GaussianBlur(5×5, σ=1.0)
     · Canny(30, 120)
     · Dilate(2×2, 1회)
     · 반전 (흰 배경 + 검은 선)
  4) CLIP ViT-B/32 임베딩 생성 (512차원) + F.normalize
  5) JSON 저장 (임베딩 + 메타데이터)
      │
      ├──▶ data/sketch/images_v2/      (21,829개 전처리 이미지)
      └──▶ data/sketch/embeddings_v2/  (21,829개 임베딩 JSON)
      │
      ▼
[vectordb.py]
  1) 임베딩 JSON 읽기 → F.normalize (unit vector 보장)
  2) 로컬 이미지 경로 자동 매핑 (KIPRIS URL 만료 대비)
  3) ChromaDB 클린 재구축 (기존 컬렉션 삭제 후 재생성)
  4) 메타데이터 포함 저장 (design_id, applicationNumber, articleName, 등록상태 등)
      │
      └──▶ data/sketch/chroma_db_v2/  (21,829건 벡터 DB)
      │
      ▼
[app.py  — Streamlit]
  1) 사용자 이미지 업로드
  2) Canny Edge Detection 스케치 변환 (DB 임베딩과 도메인 통일)
  3) CLIP 임베딩 생성 (F.normalize)
  4) Dense 검색: ChromaDB에서 Top-50 후보 추출
  5) BM25 검색: Dense 1위 articleName을 쿼리 텍스트로 활용
  6) min-max 정규화 후 가중 합산
     Hybrid Score = Dense(0.8) × dense_norm + BM25(0.2) × bm25_norm
  7) 동일 출원번호 중 최고 점수만 유지 (중복 제거)
  8) Top-10 결과 반환 및 시각화
```

## 3. 기술 스택 및 모델 설정

### 3-1. 임베딩 모델

| 항목 | 값 |
|---|---|
| 모델 | CLIP ViT-B/32 |
| 입력 해상도 | 224 × 224 |
| 출력 차원 | 512차원 |
| 정규화 | L2 정규화 (F.normalize, norm=1.0) |
| 전처리 | Canny Edge Detection 스케치 변환 |

### 3-2. Hybrid Retrieval 설정

| 항목 | 값 |
|---|---|
| Dense Weight | **0.8** |
| BM25 Weight | **0.2** |
| 초기 후보 수 (RETRIEVAL_TOP_K) | 50 |
| 최종 반환 수 (TOP_K) | 10 |
| 유사도 메트릭 | 코사인 유사도 |
| Dense Score 변환 | `1.0 - cosine_distance` |
| BM25 인덱스 필드 | `articleName` + `designSummary` |

### 3-3. 스케치 전처리 파라미터

```
GaussianBlur : kernel=(5,5), sigma=1.0
Canny        : threshold_low=30, threshold_high=120
Dilate       : kernel=2×2, iterations=1
최종 출력    : 흰 배경(255) + 검은 윤곽선(0)
```

> **전처리 일관성 보장**: `embeddings_v2.py`(DB 구축 시)와 `app.py`(쿼리 시) 동일 파라미터 적용
> → 도메인 불일치 해소, Dense 검색 정확도 향상

### 5-2. 점수 산출 방식 상세

```
[Dense Score]
  · ChromaDB에서 코사인 거리(d) 반환 (0~2 범위)
  · Dense Score = 1.0 - d  (높을수록 유사)
  · 쿼리 벡터: CLIP 스케치 임베딩, L2 정규화
  · DB 벡터:   embeddings_v2.py + vectordb.py 처리 시 L2 정규화

[BM25 Score]
  · BM25Okapi 알고리즘 (rank-bm25 라이브러리)
  · 인덱스 필드: articleName + designSummary 토큰
  · 쿼리 텍스트: Dense 1위 결과의 articleName 사용
  · 동일 물품명 → BM25 높음 / 이종 물품명 → BM25 낮음

[Hybrid Score]
  · d_norm = (dense_score - d_min) / (d_max - d_min)   ← Dense min-max 정규화
  · b_norm = (bm25_score  - b_min) / (b_max - b_min)   ← BM25 min-max 정규화
  · Hybrid = 0.8 × d_norm + 0.2 × b_norm
  · 동일 출원번호 중 Hybrid 최고 점수만 유지 (중복 제거 후 랭킹)
```

## 8. 결론

### 8-1. 핵심 성과

1. **완벽한 TOP-10 검색 성공**
   평가 13건 전체에서 Relevant 이미지가 TOP-10 이내 검색되어 **HR@10 = 100%** 달성

2. **높은 정밀도**
   13건 중 10건이 1위로 검색 (HR@1 = 76.9%), 나머지 3건도 2~3위 내 검색 성공
   **MRR = 0.923** — 실용적 검색 서비스로서 충분히 높은 수준

3. **전처리-임베딩 도메인 일관성 확보**
   `embeddings_v2.py`와 `app.py`에 동일한 Canny Edge Detection 파라미터 적용으로
   DB 임베딩과 쿼리 임베딩의 도메인 불일치 문제 완전 해소

4. **정규화 일관성 확보**
   DB 구축(`vectordb.py`)과 쿼리(`app.py`) 양쪽에 F.normalize 적용으로
   cosine 유사도 계산의 신뢰성 보장

### 8-2. 한계 및 개선 방향

| 항목 | 현황 | 개선 방향 |
|---|---|---|
| 데이터 다양성 | 99.6%가 용기/포장류 → 카테고리 단일 | 비용기 카테고리 데이터 추가 |
| Dense 분별력 | 동종 카테고리 간 점수 밀집 (0.77~0.95) | CLIP Triplet Loss 파인튜닝 |
| BM25 기여도 | 화장품 용기처럼 빈도 높은 물품명에서 낮음 | designSummary 텍스트 품질 개선 |
| 멀티뷰 활용 | 쿼리 1장만 사용 | 복수 뷰 앙상블 검색 구현 |
